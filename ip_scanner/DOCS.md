# שימוש והגדרות

## הפעלה ראשונה

התקן והפעל את התוסף. פתח את **ממשק ה־Web** או הוסף אותו לסרגל הצד. התוסף מזהה את הרשת המחוברת לשרת HA ומעדיף את הממשק של נתיב ברירת המחדל. הוא מתעלם מממשקי Docker, Supervisor ו־VPN.

אין צורך לפתוח פורטים בנתב או להזין סיסמה נוספת; הכניסה מתבצעת דרך Ingress של Home Assistant.

## תצורה

```yaml
network: auto
scan_on_start: true
scan_interval: 300
scan_timeout: 180
mdns: true
```

| הגדרה | שימוש |
| --- | --- |
| `network` | `auto` לזיהוי אוטומטי. אפשר להזין טווח CIDR כגון `192.168.1.0/24`, רק בתוך רשת שמחוברת ישירות לשרת. |
| `scan_on_start` | סריקה בהפעלת התוסף. |
| `scan_interval` | שניות בין ניסיונות סריקה. `0` מבטל סריקות מחזוריות. ברירת המחדל היא חמש דקות. |
| `scan_timeout` | מגבלת זמן לסריקת ARP/DNS, 30–600 שניות. זיהוי mDNS מוסיף עד כחמש שניות. |
| `mdns` | השלמת שמות ממכשירים כגון ESPHome, Chromecast, מדפסות ומכשירי Apple. |

שינויים בתצורה נכנסים לתוקף לאחר הפעלה מחדש. בחירת רשת בממשק תקפה עד ההפעלה מחדש; לקיבוע הבחירה יש להגדיר `network` בתצורה.

## המסך

- **סרוק את הרשת** מפעיל סריקה חדשה. בזמן סריקה הכפתור הופך ל־**עצור סריקה**.
- **מכשירים** מציג כתובות תפוסות וכתובות שנראו בעבר, עם שם, יצרן, MAC וזמן זיהוי אחרון.
- **כתובות פנויות** מציג כתובות שלא זוהו בסריקה מוצלחת, ללא זיהוי קודם בהיסטוריית הטווח.
- **טווחים** מאחד כתובות רציפות בעלות אותו מצב. החלוקה מתחשבת במעבר בין אוקטטים ואינה מוגבלת ל־‎/24.
- לחץ על כתובת במפה כדי לעבור אליה בטבלה. ברשתות גדולות המפה מחולקת לעמודים.
- כפתור **✎** מאפשר לתת שם מותאם לכתובת. השאר ריק כדי לחזור לשם שזוהה ברשת.
- **ייצוא CSV** מייצא את כל כתובות הרשת, גם אם הטבלה מסוננת או מציגה עמוד אחד.

תוצאות נשמרות רק לאחר סריקה שהסתיימה בהצלחה וכיסתה את הטווח. שגיאה, סריקה ריקה או ביטול אינם משנים את התוצאות הקודמות. עד הסיום מוצגות התוצאות מהסריקה הקודמת. כתובות שרת HA עצמו מזוהות גם לפי ממשק הרשת המקומי, ולכן אינן דורשות תגובת ARP מהשרת לעצמו.

## זמינות כתובות

״פנויה לכאורה״ אינה הבטחה: מכשיר כבוי או ישן, DHCP reservation או חסימת ARP יכולים להסתיר שימוש בכתובת. בדוק את הנתב לפני הקצאה קבועה. כתובת שזוהתה בעבר נשארת **נראתה בעבר** גם אם אינה עונה לאורך זמן.

ההיסטוריה והשמות נשמרים ב־`/data/state.json`, ונכללים בגיבויי התוסף. שמות מותאמים משויכים לכתובת IP, ולכן מומלץ לקבע DHCP עבור מכשירים ששינית את שמם. כשכתובת מחליפה MAC, שם DNS ישן לא מועבר למכשיר החדש.

## דרישות והרשאות

- Home Assistant OS עם Supervisor, ב־amd64 או aarch64.
- `host_network: true` כדי לסרוק את רשת השרת.
- `NET_RAW` כדי לבצע גילוי ARP. אין צורך ב־`NET_ADMIN`, Docker API או full access.
- השרת מקבל חיבורי Web רק מ־`172.30.32.2`, בהתאם לדרישות Ingress.
- אין סריקת שירותים או פורטים; מתבצעים גילוי ARP, חיפוש שמות DNS ו־mDNS.

## פתרון תקלות

**אין רשת נתמכת:** בדוק שהשרת מחובר לרשת. עבור רשת גדולה מ־‎/20 הגדר ידנית תת־טווח מחובר, למשל `192.168.1.0/24`. הגרסה אינה סורקת יותר מ־4,094 כתובות בכל טווח.

**שם לא מופיע:** המכשיר אינו מפרסם שם שניתן לגלות. בדוק DNS בנתב או תן שם מותאם. היצרן מזוהה באמצעות MAC רק כשמידע זה זמין, ו־MAC אקראי יכול למנוע את הזיהוי.

**mDNS אינו זמין:** תוצאות ARP ו־DNS נשארות תקינות. בדוק חסימת multicast ברשת או נסה לבטל `mdns` בתצורה.

**נכשלת סריקה:** קרא את יומן התוסף. ודא ש־NET_RAW זמין ושממשק הרשת מתאים. התוצאות הישנות נשמרות כדי לא לסמן את כל הרשת כפנויה בטעות.

**״כתובת שרת HA לא זוהתה בסריקה״ בגרסה 0.1.0:** פתח את חנות התוספים, בחר **בדיקת עדכונים**, ואז עדכן את IP Scanner ל־0.1.1 והפעל מחדש. הגרסה החדשה אינה פוסלת סריקה תקינה בגלל היעדר תגובת ARP מכתובת השרת המקומי. אין צורך להסיר את התוסף או למחוק את ההיסטוריה.

**לא ניתן לפתוח את ה־Web לפי IP של השרת:** פתח דרך Home Assistant. הגישה הישירה חסומה במכוון בהתאם לדרישות Ingress.

**יש מכשירים ברשת אורחים / VLAN שאינם מופיעים:** אם לשרת אין ממשק המחובר לרשת הזו, היא אינה זמינה לסריקת ARP מקומית. יש לחבר ממשק מתאים לשרת; הרשאות התוסף אינן עוקפות ניתוב או הפרדת רשתות.

## אימות על שרת HA

20 בדיקות לוגיקה ו־HTTP מכסות את הסריקה, כולל שרת מקומי שאינו מופיע ב־ARP, מספר כתובות מקומיות ושמירת תוצאות בעת כשל. בדיקות הבנייה ל־amd64 ול־aarch64 זמינות ב־GitHub Actions. עדיין יש לאמת את התוצאות על HA OS לאחר עדכון. לאחר התקנה יש לוודא:

1. שהבנייה וההפעלה מצליחות ביומן התוסף.
2. שהרשת שזוהתה היא הרשת של שרת HA ולא רשת של Docker.
3. שממשק Ingress נטען כולל קובצי CSS ו־JavaScript.
4. שכתובת שרת HA והנתב מופיעות כתפוסות, ושמכשירים מוכרים מזוהים.
5. שהפעלה מחדש שומרת שמות והיסטוריה.
